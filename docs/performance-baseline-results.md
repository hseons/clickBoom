# ClickBoom 性能基线实测：1.9.0 单屏矩阵与 1.11.0 对照

2026-11-23 按 [性能测量手册](performance-baseline.md) 跑完 12 个单屏场景，每场景 10 秒预热 + 60 秒采样 ×3，并在同一台机器上对 1.11.0 的改动场景做前后对照。本文只保留脱敏汇总、环境与结论；逐轮 CSV、调用栈和测试副本留在测试机本地，不入库。

## 环境与构建

| 项目 | 值 |
| --- | --- |
| 机器 | Mac mini（Apple M4，16 GB 统一内存） |
| 系统 | macOS 27.2.1（26B131） |
| 显示 | 单屏 2560 × 1440 @ 144 Hz，横屏；无外接显示器 |
| 供电 | 交流电源，低电量模式关闭 |
| 被测包 | 1.9.0（24），`dist/ClickBoom-1.9.0.dmg`，SHA-256 `cb424d0d2b216eb8baaed04fc2b5b59c8a45d7574e023b91220b565fa1eddc88`，arm64 + x86_64，ad-hoc 签名 |
| 对照包 | 1.11.0（26），同源工作区 Release 通用构建，ad-hoc 签名 |
| 采样器 | `scripts/performance-sample.c` 编译，10 秒预热 + 60 秒采样 |

- 两个包都解包到临时目录，改成独立 bundle id（`mumu.AIGG.clickBoom.perf`、`mumu.AIGG.clickBoom.perf111`）并去沙盒重签，从终端直接启动以继承输入监控授权；日常安装的 1.6.0 没有改动，也没有参与采样。
- 负载：`/tmp/mover` 按正弦轨迹往返移动指针；`/tmp/clicker` 在固定点以约 3 次/秒点击左键；前台是空白窗口，全屏场景换成无边框整屏窗口，二者都不是排除应用。
- 指标：CPU =（用户态 + 内核态）增量 / 实际经过时间，100% 表示占满一个核；内存取区间内 `phys_footprint` 峰值；`package-idle` 与 `interrupt` 唤醒分开记录，不相加。
- 干扰：采样时机器并非空闲——UURemoteServer 约 12%、kernel_task 约 5%、WindowServer 约 4%，本轮会话自身也在运行。同一批次内条件一致，数字只用于同机同批次对照，不与其它机器横向比较。
- 方法偏差：手册建议对照组逐轮交错，本轮按场景整组连跑 3 轮。`idle-off` 与 `idle-on` 的差值（0.183 个百分点）远大于同场景波动（≤ 0.014 个百分点），结论不受影响；后续复测可改为交错。

## 1.9.0 单屏矩阵

| 场景 | n | CPU %（中位数 [最小–最大]） | 峰值 MiB | package-idle 唤醒 | interrupt 唤醒 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `disabled` | 3 | 0.015 [0.006–0.025] | 23.6 | 1 [0–2] | 11 [8–14] |
| `paused` | 3 | 0.145 [0.089–0.370] | 78.4 | 8 [5–41] | 38 [27–122] |
| `excluded` | 3 | 0.002 [0.002–0.009] | 25.5 | 15 [12–18] | 22 [21–26] |
| `idle-off` | 3 | 0.002 [0.001–0.006] | 25.8 | 0 [0–1] | 22 [9–24] |
| `idle-on` | 3 | 0.185 [0.181–0.195] | 23.6 | 83 [67–88] | 123 [122–128] |
| `quiet-still` | 3 | 0.000 [0.000–0.007] | 23.4 | 0 [0–5] | 3 [2–10] |
| `fullscreen` | 3 | 0.175 [0.172–0.184] | 25.8 | 84 [82–85] | 143 [142–143] |
| `spotlight-still` | 3 | 0.002 [0.002–0.009] | 25.8 | 15 [8–18] | 22 [21–25] |
| `spotlight-move` | 3 | 8.750 [8.703–8.835] | 78.3 | 5099 [4956–5227] | 8168 [8135–8229] |
| `trail-move` | 3 | 12.046 [12.035–12.227] | 79.3 | 6540 [6293–6544] | 10440 [10421–10529] |
| `trail-max` | 3 | 15.464 [15.269–15.516] | 82.4 | 7585 [7369–8285] | 12745 [12676–12807] |
| `click-trail` | 3 | 11.329 [11.061–11.338] | 86.0 | 4447 [4192–4483] | 10869 [10864–10924] |

同批差值：

- `idle-off` → `idle-on`：CPU 0.002% → 0.185%（+0.183），package-idle 唤醒 0 → 83 次/分。
- `idle-on` → `quiet-still`：CPU 0.185% → 0.000%（−0.184），唤醒 83 → 0。
- `spotlight-still` → `spotlight-move`：CPU 0.002% → 8.750%（+8.748）。
- `trail-move` → `trail-max`：CPU 12.046% → 15.464%（+3.418）。
- `trail-max` → `click-trail`：CPU 15.464% → 11.329%（−4.134）；两者帧负载不同——`click-trail` 多出粒子，但移动路径与轨迹点数量并不完全等同，这个差值只用来判断量级，不当作「点击更便宜」的结论。

### 结论

1. **静止时唯一可重复的固定开销是全屏复查。** `idle-off` 0.002% / 0 次 package 唤醒，打开全屏静默后 `idle-on` 变成 0.185% / 83 次/分，约为每 0.5 秒一次复查（120 次/分，合并后 67–88）。三轮波动 ≤ 0.014 个百分点，属于「重复超出波动且能定位到具体路径」。
2. **免打扰时段确实停掉了复查与移动监听。** `quiet-still` 为 0.000% / 0 次 package 唤醒，与 `idle-on` 差 0.184 个百分点。
3. **全屏静默走同一条复查路径。** `fullscreen` 0.175%，与 `idle-on` 基本一致。
4. **移动场景是主要成本，并随拖尾时长上升。** 聚光环 8.75%、400 ms 拖尾 12.05%、2000 ms 拖尾 15.46%；点击叠加后仍在同一量级（11.33%）。
5. **内存**：静止 23.4–25.8 MiB；开启聚光环或拖尾后 78.3–93.1 MiB，主要是覆盖层窗口缓冲。
6. **异常值**：`paused` 第 1 轮 0.370% / 41 次唤醒，后两轮 0.145% / 0.089%；首轮包含打开面板、暂停、最小化窗口的动画残留，中位数按三轮报告。`excluded` 与 `spotlight-still` 的 15 次 package 唤醒/分是系统唤醒归因，不是本 App 的定时器。

## 1.11.0 对照

1.11.0 只改了一条静止路径：指针连续 30 秒没有移动 / 按下 / 拖拽后，全屏复查从 0.5 秒退避到 2.0 秒；指针一动立即回到 0.5 秒。对照时额外静置 35 秒，让退避在采样开始前就已生效。

| 场景 | 1.9.0 CPU % | 1.11.0 CPU % | 变化 | 1.9.0 package 唤醒 | 1.11.0 package 唤醒 | 变化 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `idle-on` | 0.185 | 0.055 | −70% | 83 | 22 | −73% |
| `fullscreen` | 0.175 | 0.052 | −70% | 84 | 31 | −63% |

1.11.0 两个场景各 3 轮：`idle-on` 0.054–0.055%、`fullscreen` 0.052–0.056%，轮间波动小于 0.005 个百分点。

移动路径回归（各 1 轮，用于确认退避没有影响活动状态）：

| 场景 | 1.9.0 CPU % | 1.11.0 CPU % | 差异 |
| --- | ---: | ---: | ---: |
| `spotlight-move` | 8.750 | 8.880 | +1.5% |
| `trail-max` | 15.464 | 15.584 | +0.8% |

差异落在 1.9.0 自身的轮间波动（0.2–1.5%）内，说明退避只作用于静止路径。

## 热点

在 `click-trail` 负载下另跑一轮 `/usr/bin/sample <pid> 15 1`，没有同时挂 CPU/唤醒采样。主线程 8358 个样本中，占比最高的应用侧栈是 SwiftUI / RenderBox 合成（`RB::SharedSurfaceGroup::render_updates`、`RB::RenderFrame::flush_pass`）与 runloop、事件等待，单个符号占比不到 0.3%，没有可归因的单一 App 函数。

结论：移动场景的成本是每帧绘制与合成的总和，不适合按热点做局部改写；这正是 1.10 自适应档位要处理的问题。本轮不再改输入派发或绘制实现。

## 结论与后续

1. 1.11.0 的全屏复查退避有明确前后对照（静止 CPU −70%、package 唤醒 −73%），保留。
2. 移动场景（8.7–15.5%）是下一版的主要目标。下一步先用 `CLICKBOOM_EFFECT_TIER=full|balanced|economy` 做三档对照，确认 144 Hz 单屏下自适应是否真的降档、降档后 CPU 与唤醒下降多少，再决定是否调阈值或改绘制。
3. 其余静止路径（`disabled`、`excluded`、`spotlight-still`、`quiet-still`）均 ≤ 0.015%，不需要优化。
4. 多屏 / 竖屏验收与 Developer ID 签名、公证仍未完成：本机没有外接显示器，证书列表里只有 Apple Development，也没有 notarytool 凭据。两项都不阻塞单屏结论，继续按条件触发。

## 复现要点

- 用独立 bundle id 的测试副本，不要直接改日常安装的包；改完 `CFBundleIdentifier` 后必须 `codesign --force --deep --sign -` 重签，否则输入监控授权会落到旧身份上。
- 从终端直接启动二进制（而不是 `open -n`），让责任进程继承终端的输入监控授权；否则状态会停在「等待输入监控权限」，采到的是无特效的空转数据。
- 采样期间用 `caffeinate -d -u` 保持显示器唤醒，并在每个场景开始前核对菜单栏状态文案与预期一致。
